# project-work：依頼を1件進める

依頼内容：$ARGUMENTS

依頼内容が空なら、何をするかを利用者に聞いて止まる。

## 手順

1. **資料を確認する**
   - `AGENTS.md` の変更の境界を守る。
   - `docs/ai/context.md`、`tasks/active.md`、`tasks/handoff.md` のうち関係するものを読む。
   - 対象、完成条件、変更しない範囲を1〜3行で書き出す。分からないことは推測で埋めず、利用者に聞く。
2. **計画する（必要なときだけ）**
   - 誤字の修正や1か所の変更などの軽い作業は、計画を書かずに3へ進む。
   - 複数のファイルにまたがる作業は、手順を3〜6行で書き、`tasks/active.md` の「現在の目的」「対象」「完了条件」を更新する。
3. **小さく実行する**：必要なファイルだけを変える。
4. **検査する**：`docs/ai/checks.md` の該当する検査を実行し、結果を `tasks/active.md` の「検証の証拠」に書く。
5. **直す**：失敗したら原因を調べて直し、4に戻る。
6. **引き継ぐ**：続きがあれば `tasks/handoff.md` を更新する。最後に、変えたもの、検査の結果（成功・失敗・未実行）、残っていることを報告する。

## 止まる条件（このプロジェクトの運用上の上限）

- 同じ失敗が2回続いたとき、または修正が3巡に達したときは、それ以上直さない。
- 原因の見立て、足りない情報、試したことを `tasks/handoff.md` の「失敗した内容」に書き、利用者に判断を求める。

## しないこと

- 公開、送信、購入、削除、権限の拡大、本番の変更、`git push` は、この手順に含まない。必要なら利用者に承認を求める。
