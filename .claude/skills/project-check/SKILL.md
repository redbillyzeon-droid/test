# project-check：仕上がりを検査する

検査する対象：$ARGUMENTS

対象が空なら、未コミットの変更全体（`git status` と `git diff`）を対象にする。

## 手順

1. 合格条件を集める：`docs/ai/checks.md` の「共通」と該当する節、`tasks/active.md` の完了条件。
2. 差分を見る：`git status`、`git diff`（追跡していない新しいファイルは中身を読む）。依頼外の変更がないかも見る。
3. 実行できる検査を実行する：`docs/ai/checks.md` に書かれたコマンドのうち、対象に関係するもの。依存パッケージの導入が必要な検査は、導入せずに「未実行（理由）」とする。
4. 別の視点で確認する：サブエージェント `project-reviewer` に、合格条件、差分、元資料の場所、3の結果を渡す。起動できないときは、自分で「依頼外の変更」「根拠のない記述」「誤り」の観点で読み直し、報告に「独立レビュー未実施」と書く。
5. 報告する：次の表で返す。

| 合格条件 | 結果（合格・不合格・未確認） | 証拠（コマンドの出力、該当箇所） |
|---|---|---|

続けて、不合格の項目、未確認の項目とその理由、依頼外の変更の有無を書く。

## しないこと

- この手順ではファイルを直さない。直すかどうかは利用者が決める。
- 合格条件を勝手にゆるめない。公開、送信、購入は含まない。
