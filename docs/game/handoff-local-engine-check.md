# 引き継ぎ：PC で戦闘画面の試作を動かして、エンジンを決める

作成：2026-10-06（クラウドのセッション）　／　宛先：利用者の PC（Windows）で作業する人、または PC 上の Claude Code セッション

## 目的

戦闘画面（`docs/game/battle-ui.md`）をティラノビルダーで作れるかを、**PC で実際にコードを動かして**確かめる。作れなければ、代わりのソフト（エンジン）を選ぶ。

利用者の指示（2026-10-06）：「多分ティラノビルダーじゃ難しいかもだから、無理なら代替えのソフトを探す必要がある。ローカルでコードを実際に動かす引き継ぎにしておいて」

## まだ確かめていないこと（PC で確かめる）

- **ティラノビルダー v3.05a**（前のセッションの記録にあったフォルダ名 `tyranobuilder_v305a_win_pro` から推測）に入っているエンジンの版は、上の Ver6.00 と違う可能性がある。
- ティラノビルダーの画面（GUI）で、手で書いた `.ks` と JavaScript を扱えるか。前のセッションでは、ティラノビルダーのプロジェクトの `.ks` を直接編集して動かしていた記録がある（`day3.ks`、`system/jinro_ui.ks` など）。同じやり方ができる可能性は高いが、未確認。
- Windows の実行ファイル（exe）に書き出したときに動くか。

## 試作のファイル

リポジトリ `redbillyzeon-droid/test`、ブランチ `claude/nifty-newton-3wjyv0` の `game/tyrano-proto/` にある。

| ファイル | 中身 |
|---|---|
| `data/others/island_battle/battle.js` | 戦闘画面の本体（JavaScript）。追加のライブラリは使っていない |
| `data/others/island_battle/battle.css` | 戦闘画面の見た目 |
| `data/scenario/battle_test.ks` | 動作確認用のシナリオ（会話 → 戦闘 → 勝ち負けで分岐） |
| `data/scenario/first.ks` | **テスト用のプロジェクトでだけ**使う first.ks。本番や前作のプロジェクトの first.ks は上書きしない |
| `tools/check_battle.js` | ブラウザで自動操作して確かめるスクリプト（Node.js と Playwright が必要）。ティラノビルダーのプレビューではなく、ブラウザで開いたときに使う |

ティラノスクリプト本体は、利用規約で再配布が禁止されているので、リポジトリには入れていない。

## PC での手順

> 前作（人狼のゲーム）のプロジェクトには、何も書きこまないこと。

1. ブランチを取ってくる：`git fetch origin claude/nifty-newton-3wjyv0` のあと、`git checkout claude/nifty-newton-3wjyv0`（クローンがなければ、先にクローンする）。
2. ティラノビルダーで、**新しいプロジェクト**を作る（例：`island_battle_test`）。画面サイズは 1280×720。
3. 新しいプロジェクトのフォルダの `data/` に、`game/tyrano-proto/data/` の中身をコピーする。`first.ks` は上書きしてよい（新しいプロジェクトなので）。
4. ティラノビルダーのプレビューで起動する。
5. 下の「合格の条件」を一つずつ確かめて、結果を記録する。
6. うまくいったら、Windows 用に書き出して（exe）、同じことを確かめる。

ティラノビルダーで新しいプロジェクトのファイルを直接編集できない、またはプレビューで `.ks` の変更が反映されない場合は、その状況をそのまま記録する（それ自体が判断の材料になる）。

## 判断のしかた

| 結果 | 次にすること |
|---|---|
| 1〜10 がすべて成功 | ティラノビルダーで作る。探索マップの画面も、同じやり方（JavaScript で画面を作る）で試作する |
| ティラノビルダーの GUI では扱いにくいが、ファイルを直接編集すれば動く | **ティラノスクリプト（ビルダーを使わず、`.ks` と JS を直接書く）に切りかえる**。エンジンは同じなので、作ったものはそのまま使える。開発ツールは「ティラノスタジオ」（公式。条件や価格は公式サイトで要確認） |
| 2〜8 のどれかが、エンジンの版の違いで動かない | 失敗した内容とエラーを記録して、クラウド側に返す。試作のコードを直す |
| ティラノ系では作れない、または作りにくい | 下の「代わりのソフトの候補」から選ぶ |

## 代わりのソフトの候補

価格・ライセンス・最新の機能は、選ぶ前に各公式サイトで確かめること（下の表は一般的な特徴で、2026-10-06 時点で公式サイトを確認したものではない）。

| ソフト | 向いている点 | 気をつける点 |
|---|---|---|
| ティラノスクリプト（ビルダーなし） | エンジンが同じなので、試作と台本の書き方がそのまま使える。クラウドで動作を確認済み | GUI での編集はできない。テキストで書く |
| Ren'Py | ノベルゲームに強い。画面（screen）を自由に作れるので、マップや戦闘画面も作れる。成人向けの作品の実績も多い | Python で書く。今ある `.ks` は書き直しになる |
| RPGツクール MZ | 正面から見る戦闘画面が最初から入っている | ノベル部分や探索マップの作り方が、今の設計と合わない部分がある。有料 |
| Godot | 自由度が高く、無料 | 作る量が多い。ノベル部分も自分で作る必要がある |
| ブラウザ向けに JavaScript で作る（Electron などで exe にする） | 試作の `battle.js` をそのまま使える | ノベル部分（文字送り、セーブ、既読スキップ）を自分で作る必要がある |

おすすめの順番：**ティラノスクリプト（ビルダーなし） → Ren'Py → Godot**。ティラノスクリプトは、今回の試作がそのまま動いたので、いちばん手戻りが少ない。
