### 1-2. 段階は1つずつ順に起きる（前提の確認）

### 2-3. 棒の計算

段階の値 T ＝ 10・30・50・70・90（段階1〜5）。イベントは、二人きりで過ごす（ハクレンは朝の稽古も）ときに「いまの好感度 +5 が T に届く」と起きる（`affection.md` 2章 A・E）。そこで、**棒が満タン ＝ 次に二人きりで過ごすとイベントが起きる好感度** にそろえる。

```
s    ＝ f.ev_<名前>（0〜5）
s = 5 のとき：棒は出さない（「段階5」とだけ出す）
次の段階   ＝ s + 1
目標  goal ＝ T[s+1] − 5        （5・25・45・65・85）
もと  base ＝ s = 0 なら 0、それ以外は T[s]   （0・10・30・50・70）
割合      ＝ (aff − base) ÷ (goal − base)。0 より下は 0、1 より上は 1
マス      ＝ 割合 × 10 の切り捨て（0〜10）
```

- goal − base は、段階0のとき5、それ以外はいつも15。1マスは好感度1.5（段階0では0.5）にあたる。
- 切り捨てにするので、**満タン（10マス）は aff ≥ goal のときだけ**。「満タンなのにイベントが起きない」を防ぐ。
- 段階のイベントを見た直後の好感度は、必ず T[s] 以上（+5 を足した値で判定し、そのあと +5 以上足すため）。棒が0より下になることはない。
- 例（`affection.md` 3章の計画）：コノハは段階1を見て25。base 10、goal 25 → 満タン。次の「コノハと過ごす」（5日目の昼、判定37）で段階2が起きる。ハクレンは8日目の朝に46（段階2。「みんなと過ごす」の +3 のあと）。base 30、goal 45 → 満タン。9日目の朝に段階3が起きる。どちらも表の流れと合う。
- 例：段階2で好感度38 → (38 − 30) ÷ 15 ＝ 0.53 → 5マス。

### 2-4. 「次に二人きりで過ごすとイベント」の印

`plan.md` の決定では「次に会うとイベント」の印と呼んでいる。同じもの。段階のイベントは二人きりの「過ごす」（ハクレンは朝の稽古も）でしか起きないので、この文書ではこう呼ぶ。

```
印 ＝ s < 5
   かつ aff ≥ goal（棒が満タン）
   かつ（次の段階 < 5、または f.day ≥ 9）
```

- 状態画面では、会える時間帯に関係なく出す（「いつ会いに行けばよいか」は、会える時間帯の欄で分かる）。
- 行動を選ぶ画面（5章）では、さらに「いまの時間帯に、その人の段階のイベントが起きる」ときだけ出す。雨の日の昼のノクティアには出さない（`noctia_1-3.md`）。朝のハクレンは「過ごす」と「鍛える（稽古）」の両方に出す（稽古でも起きるため）。
- 「みんなと過ごす」と「探索に誘う」ではイベントが起きない。誘う相手の一覧では、印の代わりに小さく「イベントは『過ごす』で」と出す（`affection.md` 6-2 の目的「みんなと過ごすではイベントが起きないことを分かるように」に合わせる）。
- 2026-10-17 決定（`plan.md`「好物」「好物つきの印の出し方」、`design/life-bond.md` 1-5。数字は目安）：「好物つき」の印を足す（好物なしでは届かないが、その人の好物を持っていて、まだ渡していなくて、aff ＋ 10 ≥ goal のとき。そのほかの条件は上の印と同じ）。行動を選ぶ画面では、「いま会える」の顔（5-2 の「中央の横」）と、過ごす一覧の［好物を渡して過ごす］のボタンに出す。［過ごす］のボタンには出さない。棒は好物なしのまま。

### 2-7. 「全員と心を通わせるまで」の欄（2026-10-17 決定。`plan.md`「全員と心を通わせるまでの目安」）

```
(1) n(ハクレン)                       ≤ R朝
(2) n(ノクティア)                     ≤ R夜
(3) n(ハクレン) + n(コノハ)           ≤ R朝 + R昼
(4) n(ノクティア) + n(イグニア)       ≤ R昼 + R夜

(6) 5人の n の合計                    ≤ R朝 + R昼 + R夜
```

- 「余り」は、それぞれの式の右辺 − 左辺。
- **K3・K4・きつい人の行は、左辺が0より大きい式だけで判定する**。左辺が0の式は、その時間帯に二人きりで過ごす必要がある人がもういないので、右辺（残り）がいくつでも寄り道を減らす理由にならない。たとえば、ノクティアが段階4になったあとの夜の残りが1回でも、(2) は見ない。

- この6つは、「1回の行動でイベントは多くても1つ」「その人の時間帯にしか起きない」だけを使った条件。時間帯の組み合わせ（朝・昼・夜の部分集合）について、そこにしか会えない人の合計が、残りの回数を超えないかを全部見ている。昼だけに会える人はいないので、昼だけの式はない。
- 好感度の差（間の会話）は見ていない。だから **式が成り立たないときは、本当に届かない**。式が成り立っても届かないことはある（その場合は警告が遅れる側に倒れる）。

判定する時点：

- 行動を選ぶ画面を出すとき（いまの時間帯を含めた R で）。K1・K2 の1行に使う。
- 1日のまとめを出すとき（次の日の朝の前の R、1-3 の表の次の日の行で。12日目のまとめは13日目の行で、R はすべて0）。K1〜K4 に使う。K2 の `f.day` の条件も、次の日の値（`f.day` + 1）で見る（案。R と時点をそろえるため）。

### 4-1. 枠

```

```

- 1日目（プロローグ）のあとは、2日目の朝の前に A を書く。
- 13日目は自由行動がないので、1日のまとめは出さない（案）。13日目の深夜のあと、すぐ14日目・夜明け前へ。

### 4-2. 手動セーブができるところ・できないところ（案）

| 場面 | 手動セーブ | 理由 |
|---|---|---|
| プロローグ〜13日目の会話画面、行動を選ぶ画面、1日のまとめ | できる | ふつうのノベルゲームと同じ |
| 状態画面・探索マップ・建てる画面などを開いている間 | できない（閉じてから） | 画面の途中の状態を保存しないため |
| 探索の戦闘の画面 | できない | 戦闘は JavaScript の中で進み、途中の状態をセーブに入れないため（`design/battle.md` 7章） |
| 14日目（「夜明け前：出発」からエンドの終わりまで） | **できない** | 下の 4-3 |

### 4-3. 決戦の途中のセーブ（2026-10-17 決定。`plan.md`「決戦の途中のセーブ」、`design/battle.md` 8章 #9）

**決定：決戦の途中にはセーブを作らない。14日目に入ったら手動セーブを止め、自動C「14日目・決戦の前」を、決戦をやり直す唯一の場所にする。**

理由：

- 前半と決着の間に、中盤・後半の会話の場面がある。その途中でセーブできると、`f.battle_state`（前半の終わりの状態）や、決着の「もう一度」に使う状態も、セーブに正しく入っていなければならない。いまの試作では、セーブを読み込んだあとの「もう一度」で止まる（`tasks/handoff.md`）。セーブできる場所をなくせば、この問題が起きない。
- 全員倒れたときは「もう一度」で、その段階の最初から罰なしでやり直せる（決定）。途中のセーブがなくても、戦闘のやり直しで困らない。
- 決戦は、前半約1〜1.5分、会話の場面、決着の数ターン（`battle.md` 6章。測っていない）。14日目の初めからやり直しても、長くない見込み。
- 14日目・夜明け前の自動Cがあるので、「タイトルに戻る」を選んでも、決戦の前に戻れる。

検討して採らなかった案：

- B：中盤・後半の会話の場面だけ手動セーブを許す。`f.battle_state` と決着の開始の状態をセーブに入れる作業が要る。利点は小さい。
- C：決着の前に自動の枠をもう1つ置く。中盤の言葉をまちがえた人が、決着だけでなく中盤から選び直せてしまい、中盤の重さが下がる。

### 4-4. 「タイトルに戻る」（決戦で全員倒れたとき）の説明

- タイトル画面に戻る。いまの戦闘の状態は残らない。
- 「続きから」で、自動C「14日目・決戦の前」を選ぶと、14日目・夜明け前（出発の前）から決戦をやり直せる。
- 相棒を選び直したいときは自動B「13日目の朝」、育成をやり直したいときは自動A（12日目の朝）か手動セーブから。
- 台本 `06_day14_battle.md` 81行・283行の説明は、この内容に直してある（2026-10-17 の版で確かめた。6章 #6）。

### 4-5. エンドのあと

**やり直しの選択肢**（決定）：

| エンド | 最後に出す選択肢 |
|---|---|
| 鬱エンド、NTR エンド | 「14日目の朝からやり直す」「タイトルに戻る」 |
| 真エンド、個別エンド5つ | 「タイトルに戻る」だけ（案。決定は鬱・NTR だけなので、いまのままにする） |

- 「14日目の朝からやり直す」（ボタンの名前は決定のまま）：自動C を読み込む。戻る状態は、14日目・夜明け前（出発の前）に書いた状態そのもの（相棒、全員の段階・好感度・`f.<名前>_resolve`、`f.mind`、`f.dev`・施設、持ち物、手がかり、`f.misaki_answer`、`f.promise_end_game` など）。決戦で決まる `f.final_mind_zero`、`f.final_retry_used`、`f.battle_state`、`f.battle_result` は、まだ決まっていない状態（0 か空）に戻る。セーブの読み込みなので、何も書き戻さなくてよい。
- 相棒は変わらない。相棒を変えたいときは「タイトルに戻る」→「続きから」→ 自動B（エンドの画面には、その説明を1行出す。案）。
- 自動C がないとき（別の周の古い状態などで読めないとき）は、自動B、それもなければタイトルへ（案）。

**回収済みエンドの記録**：

| 変数 | 中身 |
|---|---|
| `sf.end_true` | 真エンドを見たら 1 |
| `sf.end_noctia`、`sf.end_konoha`、`sf.end_kabane`、`sf.end_hakuren`、`sf.end_ignia` | 個別エンド |
| `sf.end_ntr_konoha` | NTR エンド（コノハ） |
| `sf.end_utsu` | 鬱エンド（ミサキを選んだときも、相棒が幻に負けたときも同じ1つ） |

- 書くとき：エンドの題の表示（【画面表示：ロスト・アイランド　○○エンド「…」】）のとき。スタッフロールを飛ばしても記録されるように、スタッフロールの前にする。
- タイトル画面に「エンドの記録」（8つの枠。見たものは題、見ていないものは「？？？」）を置く（案。クリック1回で開く）。
- アップデートで NTR エンドが増えたら、`sf.end_ntr_<名前>` を足す。
